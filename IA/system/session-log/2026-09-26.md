# Session du 2026-09-26 — délégation de tâches simples à un modèle local

Demande : que l'agent principal puisse confier des tâches simples à un petit
modèle local, sans lui transmettre le contexte du coffre — le modèle n'est là
que pour exécuter. Harness : AionUi pilotant Claude Code.

## Décisions prises

- **Un pont MCP, pas un sous-agent.** Les sous-agents du harness ne servent
  que les modèles de leur fournisseur ; un serveur MCP stdio relaie la
  consigne vers une API compatible OpenAI et marche avec tout harness.
- **Texte en entrée, texte en sortie.** Le modèle local ne reçoit que la
  consigne et le contenu transmis : ni fichier, ni outil, ni conversation.
  Il n'écrit rien ; l'agent principal relit et écrit seul (§7).
- **Raisonnement coupé par défaut.** Le modèle éprouvé raisonne avant de
  répondre : 200 tokens de réflexion épuisés sans réponse en 41 s, contre une
  réponse juste en 2,4 s une fois `enable_thinking` à `false`.
- **Aucune valeur de machine dans le dépôt.** Adresse du serveur et nom du
  modèle passent par `OBSIA_LOCAL_URL` et `OBSIA_LOCAL_MODEL`, posées dans la
  configuration du harness (§13.5).
- **`permission: elevated`** pour la fiche : l'adresse configurée peut
  désigner une autre machine, et le contenu transmis en sort alors.
- **Un module à part, `modeles-locaux`**, non essentiel : toutes les machines
  n'ont pas de modèle local, et le skill n'a de sens qu'avec le serveur.

## Mesures (nœud CPU, modèle de 4 B quantifié en Q4)

- écriture ~8 tokens/s, lecture ~25 tokens/s ;
- résumé d'une note de ~1 100 tokens en 3 puces : ~50 s, résumé fidèle ;
- extraction JSON des liens et images de la même note : ~55 s, rien
  d'inventé, **un lien d'exemple omis** — d'où la règle de relecture contre
  la source du skill.
