# Session du 2026-09-19 — catalogue de modules, installeur, miroir public

Demande : rendre le dépôt privé, en dériver une version publique, et installer
non pas tout mais ce qui correspond à la configuration de chacun. Trois
arbitrages posés d'entrée — le privé fait foi, catalogue *et* copie, sonder
puis confirmer — puis mise en œuvre.

## Décisions prises

- **`IA/system/modules/` devient le catalogue.** Quatorze modules ; tout agent,
  skill, MCP et tâche déclare le sien via un champ `module` obligatoire (§5).
- **`mise-en-ligne` sort de `construction` pour `deploiement`**, qui entraîne
  `conteneurs` et `controle-des-sauvegardes`. Le nouveau contrôle des renvois
  entre modules l'a révélé.
- **Le module `sauvegardes` est renommé `controle-des-sauvegardes`** : la règle
  d'unicité des noms de notes (§6) interdisait l'homonymie avec le skill.
- **Deux modes d'installation** : en place (rien n'est réécrit, seuls les
  fichiers générés se réduisent) et copie (les déclarations d'agents sont
  réduites, les tâches visant un agent absent retirées).
- **Absence de profil = catalogue complet**, donc la CI continue de vérifier
  l'ensemble.
- **Le nom du coffre parent devient une convention d'écriture**, le nom réel
  vivant dans `obsia.local.yml`.
- **Le privé fait foi, le public en est dérivé** par `publier.py`, qui exporte
  `HEAD`, vide les zones privées, passe un contrôle de fuite, régénère,
  vérifie, et ne pousse jamais.

- **Un fichier publié ne cite plus un chemin que la publication efface** :
  `mémoire/`, `brouillon/`, `.archive/`, `IA/system/session-log/`. Nommer la
  note suffit (§13.5), et `verifier_coffre.py` le contrôle.
- **Cinq fichiers cessent de supposer Arch.** `pdf`, `bureautique`, `mermaid`,
  `remediation-linux` et la fiche MCP `obsidian` donnent les trois familles de
  gestionnaires et renvoient à `obsia.local.yml`.
- **`publier.py --depot-public OWNER/NOM`** réécrit les commandes `git clone`
  de la documentation vers le dépôt public.
